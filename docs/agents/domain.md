# Domain Documentation

Before changing product behavior, read the root domain glossary and every relevant architecture decision under `docs/adr/`. This is a single-context repository.

Use canonical glossary terms in specifications, issue titles, code, tests, and user-facing copy. When a proposed change conflicts with an architecture decision, surface the conflict and supersede the decision explicitly rather than silently changing behavior.

Create or revise glossary terms and architecture decisions through the domain-modeling workflow when product language or a durable trade-off changes.
